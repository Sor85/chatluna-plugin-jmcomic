# Agent Note: JMComic v2 迁移

Status: implemented

## Problem

旧插件基于 Koishi、ChatLuna v1 与 LangChain，不能直接接入 Cordis 4 的工具、配置和生命周期；插件级工具开关与编辑配置重复了 v2 的管理能力。

## Decision

保留移动端协议、四个工具及 17 项业务配置。工具直接注册到 `ctx.tools`，移除旧工具配置块。文件传输控件通过专属 SchemaForm role 注册，使用 ui-kit，所有保存由宿主负责。

网络、队列和导出响应取消；原图和产物原子写入，同本串行，失败等待并行 worker 收尾。产物采用唯一目录，旧链接不会被重导出覆盖。批量最多十本按去重后总数检查。

下载文件由插件自身生成，使用可信入站 Session 的 Satori `bot.sendMessage` 投递，保留 buffer/file 语义。`chat.send` 会把 file:// 当作 Agent 机器路径读取并重编码，不能满足原传输契约。URL 仍只返回给模型。

## Alternatives considered

- 沿用 v1 适配层：保留已不需要的 LangChain、Zod 及工具设置。
- 新建独立配置页：重复宿主的草稿、验证与保存逻辑。
- 为测试放开沙盒本地文件读取：破坏沙盒的安全边界，拒绝采用。

## Consequences

确定性测试用本地生成的中性图册；三实现群私聊矩阵覆盖实际 buffer/url 投递和 file 模式明确拒绝。onebot-sandbox 不读取 file://，所以真实 OneBot 同路径上传需另行验收。源码单向同步到 v2 external 副本，构建、类型检查和测试都在副本执行。
