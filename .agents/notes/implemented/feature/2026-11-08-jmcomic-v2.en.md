# Agent Note: JMComic v2 migration

Status: implemented

## Problem

The old Koishi/ChatLuna v1 plugin depends on LangChain and does not fit Cordis 4 tools, configuration or lifecycle. Per-plugin tool switches and metadata editing duplicate v2 management.

## Decision

Keep the mobile protocol, four tools and 17 business settings. Register native tools with `ctx.tools` and remove legacy tool configuration. A namespaced SchemaForm renderer uses ui-kit for file transport selection; the host owns validation and saving.

Requests, queues and exports honor cancellation. Original images and artifacts are written atomically; same-album jobs serialize and failed concurrent workers settle before cleanup. Unique artifact directories prevent later exports from replacing existing links. The ten-album limit applies after deduplication.

Plugin-generated files use the trusted inbound session's Satori `bot.sendMessage`, retaining buffer/file transport semantics. `chat.send` treats file:// as an Agent-machine path and re-encodes it, which would change that contract. URL mode still returns links only.

## Alternatives considered

- Keep the v1 compatibility layer: retains unnecessary LangChain, Zod and tool settings.
- Add a separate settings page: duplicates host draft, validation and persistence logic.
- Allow local file reads in the sandbox for testing: would weaken its safety boundary and is rejected.

## Consequences

Deterministic tests use locally generated neutral albums. The three-implementation group/private matrix covers real buffer/URL delivery and explicit file-mode rejection. onebot-sandbox intentionally rejects file://; shared-path delivery still needs a real OneBot adapter. Sources synchronize one way into the v2 external workspace, where builds, type checks and tests run.
